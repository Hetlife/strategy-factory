# CE-4-03 — Execution-adapter CONTRACT (design document only; building it is gated)

**Why:** When Het authorises real capital for a class, the adapter must already be specified so a low-token model can build it under test without re-deriving architecture. Writing the contract is free and allowed (C9: "interfaces"); writing broker code is a hard rule needing his explicit, separate yes (`CLAUDE.md`).
**Executor:** CLAUDE_CODE (class B) drafts; Fable review YES.
**Scope:** `docs/capital_engine/EXECUTION_ADAPTER_CONTRACT.md`.
**Do not touch:** any code, any dependency, any secret.
**Dependencies:** CE-4-01.

## Required contents
1. Interface: `get_positions()`, `get_cash()`, `place_order(intent)` where an intent is `{profile, contestant, ticker, side, qty, limit, idempotency_key, valid_until}`, `cancel(key)`, `reconcile()`.
2. Idempotency: key = sha256(profile, contestant, ticker, date, target_weight); an adapter must refuse a duplicate key. Orders are generated from the ledger's target weights, never from a model's free text.
3. Reconciliation: nightly broker positions vs ledger; any mismatch → KILL file written automatically + NEEDS HET entry. Reconciliation runs BEFORE any new order.
4. Limits (per order and per day) read from the profile and enforced in code before the broker call; ceilings from CE-2-03; the LADDER rung capital is the hard max per contestant.
5. Secrets: names only (`PJ_strategy-factory__<BROKER>_API_KEY`) resolved from LucyOS's scoped secret store; never in the repo, never in logs; `aion scan` as the pre-commit gate.
6. Venue facts from R2: SEBI retail-algo framework obligations (algo registration, static IP, order-rate thresholds), broker API pricing, sandbox availability, crypto exchange API constraints.
7. Paper adapter first: `PaperAdapter` that fills at next close with modelled cost — the SAME interface — so the live adapter is a drop-in and every test runs against paper.
8. The authorization sentence Het must write before any adapter code exists (copy from `00_DESIGN.md` §8).
