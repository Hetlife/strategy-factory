# CE-0-04 — Phantom-day guard in `update()` (measured 21% of recorded days are fake)

**Why:** `tools/detect_phantom_days.py` run on `main` 2026-10-04 (run 37176894252): **6 of 28 judgeable days are phantom** (≥80% of tickers at exactly 0.0 return): 2026-08-27, 08-31, 09-14 (NSE holiday), 09-28, 10-01, 10-02 (Gandhi Jayanti). Each advanced every contestant's `days_on_rung` and added a paired benchmark day with no market behind it. The 2026-09-13 idempotence guard does NOT cover this (ACCELERATION_PLAN item 2 assumed it would — that assumption is now falsified): the panel gains a new DATE row on an NSE holiday because `BZ=F` (Brent) trades, and `.ffill()` turns every NSE ticker into "unchanged".

## Design (binding)
1. In `update()`, after `fetch_prices()`, compute `rets = px.pct_change()`. Define a row as REAL if the fraction of NON-macro tickers (exclude `MACRO_PROXIES`) with return exactly `0.0` (or NaN) is `< PHANTOM_UNCHANGED_FRACTION = 0.80` — the same threshold `detect_phantom_days.py` uses, kept as one named constant with a comment pointing at the detector.
2. Select `today` = the LAST REAL row's date (not simply `px.index[-1]`). If that date is already recorded → existing SKIPPED message. If the last row itself is phantom, print `PHANTOM SKIPPED: <date> (<pct>% unchanged) -- treating as no new session` and fall through to the last-real-row logic. Rationale: this also recovers a late-posting day (a stale row on day D becomes real by day D+1 and is then recorded), which plain skipping would lose.
3. `todays_ret` must be the return INTO the selected row (`rets.loc[today]`), and `append_market_log(today, px.loc[:today])` must be consistent with it.
4. Never rewrite history: the guard only decides whether to record; no existing rows change (the 6 known phantom rows stay — cleanup is ACCELERATION STEP 6, Het's call).

## Tests (acceptance)
- Synthetic panel with an injected holiday row (all NSE tickers NaN → ffilled, Brent moves): `update()` records nothing for that date and prints PHANTOM SKIPPED; the following real day IS recorded.
- Late-data case: row D stale (phantom) at cycle k, populated at cycle k+1 → D recorded at k+1, exactly once.

- `health_check.py --live` reports the 6 historical phantom days as a WARNING (information), not an error.
