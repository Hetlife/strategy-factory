# CE-2-02b — Band rebalancing for `fixed_weight` (state-aware, weekly), equity path untouched

**Why:** CE-2-02's first build returns the target weights every day, so the shield sleeve rebalances daily at zero cost — it flatters the sleeve and does not implement A1 §3 ("trade only when a sleeve drifts more than ±5 pp from target, checked weekly, at most one rebalance per week"). Fix it without changing any other strategy.
**Executor:** CLAUDE_CODE (class B). **Fable review: YES** (touches `update()`'s per-contestant loop).
**Scope:** `factory.py` (a pure helper `fixed_weight_next(cur, todays_ret, target, band, is_rebalance_day)` and ONE branch in `update()`'s per-contestant loop that runs only when `params["fn"] == "fixed_weight"`), `profiles/shield_nse.json` (add `"rebalance_weekday": 4` to the registry entry's params = Friday; unchanged otherwise), `tests/test_fixed_weight_band.py`.
**Do not touch:** any other `sig_*`, `report()`, `RULES`/`LADDER`/`COST_PER_SIDE`, the equity golden file, other profiles.
**Dependencies:** CE-2-02 (merged into the work branch).

## Design (binding)
- State is the contestant's existing `positions` dict (ticker → weight after yesterday's close). No new ledger fields.
- Each day: drift `cur` by today's returns (`w_i * (1 + r_i)`, renormalised to the pre-drift gross); if `cur` is empty (first day) → enter the TARGET (initial allocation; costs apply as for any entry).
- If today is the rebalance weekday (`pd.Timestamp(today).weekday() == rebalance_weekday`) AND `max_i |drifted_w_i - target_i| > band` → positions = target (turnover = sum of abs weight changes, costed by the existing path). Otherwise positions = drifted weights (zero turnover).
- At most one rebalance per calendar week follows from the weekday rule. Missing tickers: drop and renormalise as CE-2-02 does, BUT if the cash sleeve ticker (`BENCHMARK`) is missing, hold the previous positions unchanged and print a WARNING (fail closed; do not silently turn the sleeve into 100% risk assets).
- Equity profile and every non-`fixed_weight` strategy: byte-identical (golden fingerprint unchanged — do NOT regenerate it).

## Acceptance
- `tests/test_fixed_weight_band.py` on the pure helper: (a) first day enters target; (b) drift under the band on the rebalance day → no trade, positions drifted; (c) drift over the band on a non-rebalance day → no trade; (d) drift over the band on the rebalance day → exactly target, turnover > 0; (e) never two rebalances in one ISO week over 60 synthetic days with large drifts; (f) cash ticker missing → positions unchanged + warning.
- A 40-cycle `FACTORY_PROFILE=shield_nse` synthetic run (temp factory copy) shows turnover > 0 only on rebalance days, and the shield report() output pasted.
- Full suite OK twice; equity golden unchanged.
