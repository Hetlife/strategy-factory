# CE-4-01 — Capital activation gates, codified (read-only evaluator)

**Why:** LucyOS contract C9: "Capital activation requires independent validation first." Today the gates live in prose (`EXECUTION_PLAN.md` §4-6, `00_DESIGN.md` §6). A deterministic evaluator prints GREEN/AMBER/RED per class so no session, and no owner, has to remember them — and so a RED can never be argued away.
**Executor:** CLAUDE_CODE (class B).
**Scope:** `portfolio/gates.py` (+ `tools/gates_report.py` CLI), `tests/test_gates.py`, wired into `supervisor.yml` output and the Trading Floor state.
**Do not touch:** execution of any kind; the evaluator prints only.
**Dependencies:** CE-2-03.

## Gate definition per class (evaluate ALL; any RED → RED)
- G1 evidence: ≥ 1 contestant PROMOTED by `promotion_check()` to rung 1 with ≥ `RULES.min_days_on_rung` days (ladder, Law 3).
- G2 independent validation: a file `docs/capital_engine/validation/<class>_<contestant>_<date>.md` exists, authored in a DIFFERENT session from the one that built the strategy, re-deriving the verdict (judge.py) and checking data integrity (health harness clean, no duplicate/phantom days).
- G3 portfolio: aggregator drawdown within the limit; class exposure after activation ≤ ceiling.
- G4 owner: a dated line in `.autonomous/het_directives.md` matching `AUTHORIZE REAL CAPITAL <class> <contestant> <amount>` — fresh, in-session, specific. (The evaluator checks presence; a human still acts.)
- G5 infrastructure (for any class): kill switch file check exists (CE-4-02), reconciliation design exists (CE-4-03).
