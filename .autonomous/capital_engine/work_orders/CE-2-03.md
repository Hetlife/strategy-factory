# CE-2-03 — Portfolio aggregator (read-only): class exposure, ceilings, drawdown, kill status

**Why:** The three classes need one honest top-level view: how much capital each class has EARNED (via its ladder), against its CEILING (A 50% / B 30% / C 20% of total — ceilings, not targets), portfolio-level drawdown, and whether any kill condition in `EXECUTION_PLAN.md` §5 or `docs/capital_engine/00_DESIGN.md` §6 is tripped. Read-only, printed, same tier as `agents/`.
**Executor:** CLAUDE_CODE (class B).
**Scope:** `portfolio/__init__.py`, `portfolio/aggregate.py` (reads every enabled profile's ledger; computes per-class real-money exposure = sum of `LADDER[rung]` for rung ≥ 1, paper equity curves, combined equity curve weighted by ceilings for the paper view, portfolio max drawdown; prints a table and writes `factory_state/portfolio_view.json`), `tools/build_trading_floor_state.py` (+ one section), `agents/risk_manager/risk_manager.py` (call the aggregator for the portfolio-wide flag it already approximates).
**Do not touch:** any ledger write path; `RULES`/`LADDER`.
**Dependencies:** CE-1-02 (profiles), CE-1-03.

## Acceptance
- With only `equity_nse` enabled, the output shows A2 (equity arena) exposure Rs 0, ceilings as configured, and no kill tripped — identical numbers to today's `risk_manager` aggregate-exposure line.
- Unit test with two synthetic ledgers proves ceiling math and drawdown math.
- Dashboard state JSON gains a `portfolio` key; Trading Floor Artifact renders it (screenshot in evidence).
