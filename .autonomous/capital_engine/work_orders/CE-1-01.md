# CE-1-01 — Golden-master regression harness for `factory.py`

**Why:** Phase 1 generalizes the engine so it can run more than one asset class. Nothing may change the equity arena's behaviour by even one byte. Today the "testing standard" is a manual recipe; this turns it into a repeatable script every later order runs.
**Executor:** CLAUDE_CODE (class B). LOCAL_MODEL may draft the synthetic-panel generator; CLAUDE_CODE reviews.
**Scope:** `tests/__init__.py`, `tests/synthetic_panel.py` (seeded random-walk panel for `ALL_TICKERS` + `BENCHMARK` + `MACRO_PROXIES`, with injectable shock days), `tests/test_golden_master.py`, `tests/golden/equity_nse.sha256` (the fingerprint), `.github/workflows/tests.yml` (runs on pull_request; pandas/numpy only).
**Do not touch:** `factory.py` logic, `factory_state/**`, `RULES`/`LADDER`/`COST_PER_SIDE`.
**Dependencies:** CE-0-01 (so the workflow can run on PRs).

## Steps
1. Harness copies `factory.py` + `factory_state/` into a temp dir, sets `STATE_DIR` there, monkeypatches `fetch_prices()` to return the seeded panel one row further each cycle.
2. Run 40 × `update()` then `report()`; serialize the resulting ledger with `json.dumps(sort_keys=True)`; sha256 it.
3. First run writes `tests/golden/equity_nse.sha256`; later runs compare. A mismatch fails with a unified diff of the two ledgers (truncate to 200 lines).
4. Also assert: untouched registry entries are byte-identical to the committed ledger's registry; the paper-holding-tax and idempotence guard fire (second `update()` on the same panel row returns the SKIPPED message).

## Acceptance
- `python3 -m unittest tests.test_golden_master` passes twice in a row locally (deterministic), and in the new workflow.
- Running it against a deliberately altered constant (e.g. `PAPER_HOLDING_TAX_WEEKLY`) in the temp copy FAILS — prove the harness can detect a change. Paste both outputs.

**Rollback:** delete `tests/` — no production path touched.
