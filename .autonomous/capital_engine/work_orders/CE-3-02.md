# CE-3-02 — Crypto data feasibility on GitHub Actions (free, deterministic)

**Why:** The sandbox cannot reach Yahoo Finance; GitHub Actions can. Before writing a crypto profile we must know whether `yfinance` returns daily 7-day/week bars for the chosen coins, how far back, and how often rows are missing. Pattern: the existing `diagnose_*.yml` workflows.
**Executor:** CLAUDE_CODE writes the tool + workflow; DET runs it; LOCAL_MODEL may summarise the log.
**Scope:** `tools/diagnose_crypto_data.py` (download `BTC-USD, ETH-USD, …` for 5y; print rows per ticker, first/last date, weekend coverage %, gaps > 1 day, and a 10-row tail), `.github/workflows/diagnose_crypto_data.yml` (workflow_dispatch only), `docs/capital_engine/research/R3_crypto_data_feasibility.md` (paste the log).
**Do not touch:** `factory.py`, any profile.
**Dependencies:** CE-0-01 (workflow must be on `main` to dispatch).

## Acceptance
- R3 contains the real run URL and output; it states a verdict per ticker: USABLE / GAPPY / UNUSABLE.
- Fallback noted if yfinance is unusable: Binance public REST klines (no key) — recorded as a candidate, not built.
